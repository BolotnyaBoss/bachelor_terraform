## Overview

The `modules` folder is a core part of the infrastructure-as-code (IaC) project that encapsulates reusable Terraform modules for provisioning and managing key Azure cloud resources. Each subfolder within `modules` represents a discrete, self-contained component responsible for automating the deployment and configuration of specific Azure services such as Resource Groups, Storage Accounts, Data Factories, SQL Servers, and SQL Databases.

These modules collectively enable infrastructure consistency, repeatability, and scalability by codifying best practices for Azure resource deployment. Using this modular approach provides clear separation of concerns and simplified management of complex cloud environments by allowing individual components to be composed and orchestrated in larger project deployments.


## Usage

To utilize these Terraform modules in your infrastructure project, follow these general steps:

1. **Reference the Modules:**
   Import the required modules into your Terraform root configuration using the `module` block with the relative path pointing to the desired module folder, for example:

   ```hcl
   module "resource_group" {
     source = "./modules/resource-group"

     name     = "my-resource-group"
     location = "East US"
   }

   module "storage_account" {
     source              = "./modules/storage-account"
     resource_group_name = module.resource_group.name
     account_name        = "mystorageaccount"
     location            = module.resource_group.location
   }
   ```

2. **Supply Required Variables:**
   Each module defines input variables that must be provided to successfully deploy the resources. Review each module’s `variables.tf.md` to understand required parameters.

3. **Apply Infrastructure:**
   Execute `terraform init` and `terraform apply` to provision the resources as defined by the composed modules.

4. **Integration:**
   Outputs from one module (e.g. resource group name, storage account keys) can be fed into others to tightly couple the infrastructure components, achieving a robust and interconnected cloud deployment.

This modular structure simplifies replication of infrastructure environments, enables easy customization, and promotes collaboration by breaking down a complex cloud architecture into manageable parts.


## Useful details

- **Folder Structure:**
  - `resource-group`: Defines and manages Azure Resource Groups — the logical containers for organizing Azure resources.
  - `storage-account`: Provisions Azure Storage Accounts, including containers and blob storage, essential for scalable cloud storage needs.
  - `data-factory`: Automates deployment of Azure Data Factory resources, crucial for orchestrating data integration and transformation workflows.
  - `sql-server`: Creates Azure SQL Servers with administrative and AAD integration, forming the backbone for relational database services.
  - `sql-database`: Defines Azure SQL Databases on existing SQL Servers, automating database instance creation and configuration details.

- **Outputs & Variables:**
  Each module includes detailed input variables and output definitions to facilitate parameterization and enable seamless integration with other infrastructure components.

- **Extensibility:**
  The modular design allows for easy extension or modification to support additional Azure features, compliance requirements, or project-specific customizations.

- **Documentation:**
  Each module contains its own README and documentation files explaining its individual purpose, variables, outputs, and usage examples for focused reference.

By leveraging these Terraform modules, teams can significantly reduce manual configuration errors, accelerate infrastructure delivery pipelines, and maintain a consistent cloud environment aligned with best practices.
