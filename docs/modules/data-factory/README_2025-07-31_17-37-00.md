## Overview
The `data-factory` folder contains Terraform configuration files aimed at provisioning and managing Azure Data Factory resources along with their related Azure Storage accounts. This module plays a critical role in cloud-based data integration projects by enabling automated orchestration of data workflows on Azure. Specifically, it allows for the creation of an Azure Data Factory instance, links it to an existing Azure Storage Account, and establishes the infrastructure needed to manage data pipelines and processes efficiently.

The primary purpose of this module is to facilitate infrastructure-as-code deployment of key Azure components for building scalable and maintainable data pipelines. It abstracts away the underlying complexity of manual Azure resource setup by providing a parametrized, reusable architecture that fits into larger data engineering or analytics platforms.

## Usage
To use this module in a Terraform project, follow these general steps:

1. **Prepare your environment**  
   Ensure you have Terraform installed and authenticated with an Azure subscription where you want to provision resources.

2. **Configure input variables**  
   Edit or override the variables defined in `variables.tf` to specify values such as:
   - Azure Resource Group name where the resources reside.
   - Existing Azure Storage Account details that will be linked to the Data Factory.
   - Desired name and region for the Azure Data Factory instance.

3. **Include the module**  
   In your root Terraform configuration, call this module, for example:
   ```hcl
   module "data_factory" {
     source = "./modules/data-factory"
     
     resource_group_name         = "my-resource-group"
     storage_account_name        = "existingstorageaccount"
     data_factory_name           = "my-data-factory"
     location                   = "East US"
   }
   ```

4. **Apply the configuration**  
   Run:
   ```bash
   terraform init
   terraform plan
   terraform apply
   ```
   This will provision the Azure Data Factory instance and link it to your specified Azure Blob Storage.

## Useful details
- The `main.tf` file orchestrates the creation of the Azure Data Factory and establishes the linked service between the Data Factory and the existing Azure Storage Account. This pattern is crucial for data integration pipelines requiring blob storage as a source or sink for data.

- The `variables.tf` file centralizes variable definitions, making this module easily adaptable to different environments or projects without modifying the core resource definitions.

- By using this module, infrastructure teams and developers can automate and consistently reproduce Azure data integration environments, enhancing reliability and reducing manual errors.

- This setup serves as a foundational building block for larger workflows involving ETL/ELT pipelines, data movement, and transformation logic typically orchestrated within Azure Data Factory.

- It assumes the existence of an Azure Storage Account, enabling separation of concerns where storage and data orchestration lifecycles can be managed independently.
