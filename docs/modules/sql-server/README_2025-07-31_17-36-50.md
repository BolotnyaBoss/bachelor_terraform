## Overview
The `sql-server` folder contains Terraform configuration files designed to provision and manage an Azure SQL Server instance within a cloud infrastructure environment. Its primary purpose is to provide an automated, repeatable, and manageable way to deploy an Azure SQL Server, including setting up administrative credentials and configuring an Azure Active Directory (AAD) administrator for integrated identity management. This module typically forms part of a broader infrastructure-as-code (IaC) project, enabling consistent and scalable deployment of database services as part of a larger cloud infrastructure.

By using this module, teams can ensure that their SQL Server resources are deployed securely and conform to organizational standards without manual intervention. The module integrates seamlessly with other Terraform modules and can be referenced or extended in larger Terraform projects that manage multi-tier cloud applications.

## Usage
To use the `sql-server` Terraform module, follow these steps:

1. **Configure variables:**  
   Set the required input variables defined in `variables.tf.md` such as `server_name`, `administrator_login`, `administrator_password`, `aad_admin_object_id`, and location-related settings. These can be passed via a Terraform variables file or directly in your Terraform configuration.

2. **Invoke the module:**  
   Within your Terraform root module or another module, include the sql-server module using a `module` block referencing the relative path or repository location.

   ```hcl
   module "sql_server" {
     source                 = "./modules/sql-server"
     server_name            = "my-sql-server"
     administrator_login    = "sqladmin"
     administrator_password = "P@ssw0rd123!"
     aad_admin_object_id    = "00000000-0000-0000-0000-000000000000"
     resource_group_name    = "my-resource-group"
     location               = "eastus"
   }
   ```

3. **Apply the configuration:**  
   After defining the variables and integrating the module, run `terraform init` to initialize, followed by `terraform apply` to provision the Azure SQL Server.

4. **Retrieve outputs:**  
   Reference outputs from `outputs.tf.md`, especially the `id` of the SQL Server, for use in downstream modules or automation scripts.

## Useful details
- **Variable separation:** The variables defining server properties and credentials are centralized in `variables.tf.md`. This design promotes reusability and maintainability by allowing easy modification of deployment parameters without altering the core resource definitions.

- **Resource provisioning:** The main resource creation occurs in `main.tf.md` using the `azurerm_mssql_server` resource, ensuring compliance with Azure best practices and enabling automated deployment of necessary SQL Server instances.

- **Output handling:** The `outputs.tf.md` file exports key resource identifiers, notably the SQL Server `id`, allowing downstream resources to reference this server seamlessly—important for establishing dependencies or integrating with other modules like SQL databases, firewall rules, or monitoring services.

- **AAD Integration:** The module configures Azure Active Directory administrators on the SQL Server, enabling centralized identity management and improved security posture aligned with enterprise standards.

- **Extensibility:** This module can be incorporated into larger Terraform projects managing complex cloud infrastructure stacks. Users may extend it by adding variables, outputs, or resources as needed.

- **Security:** Sensitive variables such as administrator passwords should ideally be managed using secure Terraform practices, such as environment variables, secret management systems, or Terraform Cloud workspaces with variable encryption to prevent exposure.

This structured approach encapsulates Azure SQL Server infrastructure deployment within an automated IaC pipeline, facilitating consistent, secure, and maintainable cloud solutions.
